# 變數清單（給後端工程師）

六封課程通知信的樣板在 `dist/emails/`。這份清單是**要接的介面**，不要從 HTML 裡猜。

樣板裡的系統變數一律寫成 `{{變數名}}`，寄信前由寄信端替換。
`dist/emails/` 的檔案**刻意保留 `{{ }}` 原樣**，那不是建置失敗。

領域詞彙（報名通知／開課通知／班級名稱／梯次名稱…）見 `CONTEXT.md`。

---

## ⚠️ 三件最容易接錯的事

### 1. 主旨列的變數不在 HTML body 裡

主旨是寄信端自己組的字串，不會從 `<body>` 撈到。每封信的主旨寫在檔案的 `<title>` 與檔頭註解裡，也列在下面的「主旨列」一節。**漏掉主旨列的變數，寄出去的信主旨會直接帶著 `{{梯次名稱}}` 字樣。**

### 2. `{{梯次名稱}}` 是兩個欄位，不是一個

同一個班期，在**報名通知**與**開課通知**使用**不同的顯示字串**：

| | 報名通知 | 開課通知 |
|---|---|---|
| 成人矯正班 | `成人矯正班第36期` | `發音聽力矯正課成人班–52100組` |
| 大師班 | `SoR大師班第17期` | `大師班-發音聽力矯正課–52100組` |

兩者長得很像但**不可互換**，資料庫要各存一欄，課務也各自維護。決策與後果見 `docs/adr/0001-two-cohort-display-names.md`。

兒童課程不受影響：其梯次名稱即課程名稱，兩封信共用同一個值。

### 3. `{{班級名稱}}` 與 `{{梯次名稱}}` 是不透明字串

由課務撰寫，**不可由系統拼接**。它們內含階段、班別代碼、授課老師、期數或組別，但組合格式因課程而異（`第一階-04｜B200｜吳鈺文 老師群組` vs `31-539成人班｜李莉菁 老師群組`）。當成單一字串搬運，不要拆成欄位再組回去。

## 變數

### `{{上課者姓名}}`

- **語意**：實際參與課程的人。兒童課程指孩子（收信的是家長）；成人與大師班中上課者即報名人本人。
- **型別**：字串，中文姓名。例：`王小明`、`陳美惠`
- **出現在**：
  - ① 主旨列、稱謂（`{{上課者姓名}} 的家長 您好：`）、可複製的群組自我介紹範本
  - ② 主旨列、稱謂
  - ③ 稱謂（`親愛的 {{上課者姓名}} 您好：`）
  - ⑤ 稱謂、要回傳給官方客服的可複製區塊（`上課者姓名：`）
- **缺值**：①② 視為錯誤，不得寄出（主旨列靠它辨識是哪個孩子）。③⑤ 可降級為「親愛的學員 您好：」，但這需要寄信端自行處理。

> **與 issue 規格的差異，請課務確認**：#5 列的信 ③⑤ 變數不含姓名，但這兩封信的文案原稿都有課務標為變數的 `[@姓名]`，而 #1 的定案規則是「以課務標記的欄位為準」。這裡照 #1 的規則保留了姓名。若確定不帶，刪掉稱謂裡的變數即可，其餘不受影響。

### `{{梯次名稱}}`

- **語意**：主旨列上用來識別「這封信屬於哪一門課、哪一期」的字串。**報名通知與開課通知是兩個不同的欄位**，見上方第 2 點。
- **型別**：不透明字串，課務撰寫。例：`拼讀小達人第一階01(8月班)`、`成人矯正班第36期`、`發音聽力矯正課成人班–52100組`
- **出現在**：**六封信的主旨列**。內文只有 ⑤ 用到：歡迎語（`歡迎您加入【{{梯次名稱}}】的學習行列！`）與要回傳給官方客服的可複製區塊。①②③④⑥ 的內文不出現。
- **缺值**：視為錯誤，不得寄出。

### `{{報到關鍵字}}`

- **語意**：**報到**時要傳送給**官方客服**的字串，用以識別報名的班期。隨班期變動。
- **型別**：字串。通常是梯次名稱後面加「報到」。例：`拼讀小達人第一階01(8月班)報到`、`成人矯正班第36期報到`
- **出現在**：① ③ 的步驟 2，放在一個關鍵字方塊裡（收件人要原樣複製傳送）。
- **缺值**：視為錯誤，不得寄出——這封信的唯一目的就是要收件人送出這個字串。

### `{{班級名稱}}`

- **語意**：識別一個開課班級的字串，內含階段、班別代碼與授課老師。
- **型別**：不透明字串，課務撰寫。例：`第一階-04｜B200｜吳鈺文 老師群組`、`31-539成人班｜李莉菁 老師群組`
- **出現在**：② ④ ⑥ 的步驟 1。
- **缺值**：視為錯誤，不得寄出。

### `{{班級群組連結}}`

- **語意**：單一開課班級專屬的 LINE **班級群組**邀請連結。每班一個，隨班期變動。
- **型別**：URL。例：`https://line.me/R/ti/g/sXuxbd9RSR`
- **出現在**：② ④ ⑥ 的「加入班級群組」按鈕。它同時是 HTML `<a href>` 與 Outlook VML 的 `href`，**兩處都要替換**（樣板裡是同一個 `{{ }}` 出現兩次，字串替換即可）。
- **缺值**：視為錯誤，不得寄出。空值會產生一個點了沒反應的按鈕。

### `{{開課日期}}`（僅 ②）

- **語意**：兒童課程的正式開課日。首日為師生交流相見歡。
- **型別**：字串，**含星期、不含時間**。例：`7/10 (五)`
- **出現在**：② 的「課程與線上互動資訊」與其下的提示區塊，**同一封信出現兩次**。
- **缺值**：視為錯誤，不得寄出。

### `{{互動時間}}`（僅 ②）

- **語意**：正音師線上互動時間。與正式開課日期分開，是每週固定的互動時段。
- **型別**：字串，含星期與時段。例：`每週二及週五 晚上 20:00 – 20:40`（時間區間用半形 en dash `–`）
- **出現在**：② 的「課程與線上互動資訊」，一次。
- **缺值**：視為錯誤，不得寄出。

### `{{師生相見歡}}`（④ ⑥）

- **語意**：正式開課前的說明場次，會說明課程安排與配合事項。與正式開課日是**兩個不同的日期**。
- **型別**：字串，**含日期、星期與時段**。例：`2026/08/14 (五) 21:00 – 22:00`
- **出現在**：④ ⑥ 的「課程與時間安排／關鍵日程」，一次。
- **缺值**：視為錯誤，不得寄出。

### `{{正式開課日}}`（④ ⑥）

- **語意**：成人課程第一堂正課的日期時間。在師生相見歡之後。
- **型別**：字串，含日期、星期與時段。例：`2026/08/21 (五) 21:00 – 22:00`
- **出現在**：④ ⑥ 的「課程與時間安排／關鍵日程」，一次。
- **缺值**：視為錯誤，不得寄出。

### `{{常態上課時間}}`（④ ⑥）

- **語意**：正式開課後每週固定的上課時段。不含日期。
- **型別**：字串，含星期與時段。例：`每週五 晚上 21:00 – 22:00`
- **出現在**：④ ⑥ 的「課程與時間安排／常態上課時間」，一次。
- **缺值**：視為錯誤，不得寄出。

### `{{學號}}`（僅 ⑤）

- **語意**：大師班上課者的專屬學號，後續驗證與上課會使用。
- **型別**：字串。格式待後端確認，樣板不做假設。預覽頁用的假資料是 `M17-0042`。
- **出現在**：⑤ 的學號方塊，以及要回傳給官方客服的可複製區塊，**同一封信出現兩次**。
- **缺值**：視為錯誤，不得寄出。

## 寄信端須知

**寄件人名稱**建議統一為「蕭博士 SoR 美語」。

**不設回信信箱**是已定案的決定。因此頁尾的「官方客服 LINE」與「前往官網」是收件人**唯一**的求助管道——這兩個連結壞掉等於收件人求助無門。

**寄信基數**：六封信全部只處理**單筆報名**，樣板裡沒有多筆報名的重複區塊。一位上課者配一個班級是一筆報名，一筆報名寄一封報名通知與一封開課通知。同一張訂單、同一門課，只要時段不同就各自寄出。詳見 `CONTEXT.md`。

**preheader（收件匣預覽文字）目前刻意不寫。** 收件人在收件匣看到的預覽會是信件開頭的文字。

## 未決（會影響這份清單）

### 大師班的開課通知可能寄兩封（待 #7）

大師班的授課內容涵蓋成人矯正班，兩者的開課通知目前指向**同一個班級群組、同一組日期**。若系統為此建立兩筆報名，依「一筆報名一封開課通知」的規則，該上課者會收到**兩封內容幾乎相同、連結完全相同**的信。

**去重規則屬後端邏輯，樣板無法處理。** 需要先確認系統怎麼建報名紀錄，再決定是否要在寄信端加去重。

### 孩子的年級（待 #7）

② 的群組自我介紹範本目前是：

> 大家好，我是 {{上課者姓名}} 的爸爸/媽媽，寶貝今年（請填入年級），很高興跟大家一起學習！

孩子姓名由系統帶入，**年級留給家長自己填**。若系統有年級欄位，這裡可以再多一個 `{{年級}}` 變數，整段預先填好讓家長直接複製。

### 同時段的兩個孩子是不是也兩封（待 #7）

已確認「不同時段兩個孩子＝兩封」。同一時段若會**合併成一封**，報名通知就需要涵蓋多筆報名的重複區塊——那會改變樣板結構，不只是加一個變數。

### 品牌 tagline 的正確字串（待 #10）

頁尾那行 `FoR you, FoR me, FoRmosa.` 目前照 Figma 匯出時的結論寫死在 `src/constants.js`，但那則結論本身是從 Figma 素材讀出來的，**先前曾讀到不一致的版本**（`Talk you, Talk me, Talkmore`）。上線前請品牌端確認一次正確字串與大小寫。它出現在六封信的頁尾。

### 官網與社群網址（待 #10）

`src/constants.js` 裡還剩下的 `https://REPLACE-ME.example.com/...` 是佔位符，**上線前必須替換**：官網網址，與 YouTube / Facebook / Instagram 三個連結。它們都在頁尾。

## logo 掛在 GitHub Pages 上

logo 網址必須**長期穩定、不隨官網改版失效**。舊信裡的圖若掛在舊站，網站重建後會全部斷掉——這是既有通知信已經存在的風險。

所以圖不放官網，跟樣板一起走版控：`assets/logo/` 的兩個檔案由建置複製到 `dist/assets/logo/`，而 `dist/` 就是這個 repo 的 GitHub Pages 站台根目錄。六封信的 `<img src>` 指向

```
https://joyho37.github.io/sor-email/assets/logo/logo-primary@2x.png   頁首（白底，標準版）
https://joyho37.github.io/sor-email/assets/logo/logo-inverse@2x.png   頁尾（深色底，反白版）
```

代價是這組網址綁在 repo 上：**repo 必須保持公開，不能改名或轉移**，否則所有已寄出的信都會破圖。若之後要換到別的空間，改 `src/constants.js` 的 `PAGES_URL` 重新建置即可，但**已經寄出去的信改不了**。

寄信端不必做任何事：網址已經寫死在 `dist/emails/` 的 HTML 裡，不是變數。
